# Decisions and open questions

## Confirmed source facts

- Group 1 supplies the IDs and labels for three equipment classes and 30 subsystem/component reference rows.
- Group 1 says no subsystem IDs are defined in the supplied taxonomy.
- Model notes are illustrative; no real equipment model is documented in the equipment reference.
- M04 v1.1 is prepared for cross-group review; formal approval is pending.
- M04 assigns physical DDL/migrations to M05 and leaves hierarchy levels, identifier strategy and Common Data Model approval unresolved.
- The public repository README describes Java/Spring Boot, while the task prompt specifies Node.js + Express.

## Implementation choices made provisionally

- Candidate schema uses PostgreSQL `public` schema and lower_snake_case identifiers.
- `equipment_class_id` is the source ID and class-table primary key.
- `asset_id` uses `BIGINT GENERATED BY DEFAULT AS IDENTITY`; this is an implementation choice, not an approved project standard.
- `asset_node` is an arbitrary-depth adjacency list. Parent FK, self-parent rejection and cycle detection are implemented in SQL.
- `asset_level` and `status` remain nonblank text rather than enum/check-constrained vocabularies.
- `m06_equipment_component_reference` is a namespaced provenance table, not an approved taxonomy entity.
- Seed conflicts are ignored rather than overwriting reviewed or existing values.
