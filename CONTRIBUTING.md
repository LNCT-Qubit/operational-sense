# Contributing

1. Open an issue describing the problem, proposed change, and affected workstream.
2. Keep domain rules, API contracts, and data schemas documented alongside code.
3. Never commit confidential plant data, credentials, or unapproved personal data.
4. Include tests or validation evidence for behavior and schema changes.
5. Preserve provenance for external sources and clearly label synthetic examples.
6. Submit a pull request using the repository template and identify risks or migration needs.
7. Do not change criticality weights, score bands, or override rules without a documented review decision.
